# 마이클라이밋 MyClimate 기획서 (접수양식 02장 초안)

> 팀명·대표자·연락처 등 참가자 정보는 **접수양식 01에 기재**합니다(이 문서에는 쓰지 않음).
> 이 문서의 "동작"은 모두 **Pleos Connect 에뮬레이터(Virtual Console)** 기준이며, 날씨·대기질은 동의 시 선택 지역의 Open-Meteo 값, 아니면 가공 샘플입니다. 실차 결과가 아닙니다.
> 표기: **[기획 가정]** = 기획 원문의 가정(검증하지 않음), **[구현]** = 코드·테스트·에뮬레이터로 확인(날씨·대기질 실호출·동의 팝업은 2026-11-11 후속 검증에서 에뮬레이터로 확인), **[미구현/미검증]** = 6장 한계 참조.

## 1. 앱 한 줄 소개

탈 때마다 공조·시트·핸들 열선을 다시 맞춰야 하는 번거로움을, 저장한 프로필을 정차 중 한 번에 적용하고 외기온·날씨 규칙으로 보조하는 앱으로 줄입니다.

## 2. 기획 배경

- **주목한 순간**: 한 차를 함께 쓰면 탈 때마다 온도·풍량·내기순환·시트 열선을 다시 맞춰야 합니다. 시트 위치·미러는 운전자별로 저장되지만 공조는 마지막 설정이 남는 경우가 많습니다. 주행 중 공조 버튼 조작은 시선 분산으로 이어집니다. (기획 원문의 문제 인식)
- **왜 차량인가**: 공조·시트·외기온도·기어(주행/정차) 신호를 차량이 알고 있어, 사용자가 매번 조작하지 않아도 상황에 맞게 제안·적용할 수 있습니다.
- **주행 안전 관점**: 조작과 편집은 정차 중에만 허용하고, 주행 중에는 한 줄 안내만 보여주도록 설계했습니다.

## 3. 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 상태 |
|---|---|---|
| 공조 프로필 | 최대 8개. 항목별 '적용' 스위치(꺼짐 = 건드리지 않음). 현재 차량 값으로 새 프로필 생성, 정차 중 선택·편집·삭제(삭제 확인 팝업). 프로필 이름은 자동 부여(편집 불가) | [구현] |
| 자동 적용 | 앱 실행·정차(P) 전환 시 정차 구간당 1회, 차량 연결과 capability 확인 후 적용. 에뮬레이터에서 프로필 7개 항목 적용 확인 | [구현] |
| 상황별 규칙 | 외기온도 구간·시간대(자정 넘김)·날씨 조건 -> 설정 패치. 더 구체적인 규칙 우선, 기본 규칙(폭염/한파/비·눈/심야) 포함, 정차 중 추가·켜기/끄기·삭제 | [구현] 날씨는 동의 시 선택 지역 실시간(Open-Meteo), 아니면 가공 샘플 |
| 습관 학습·제안 | 시트 열선/통풍·핸들 열선·에어컨·내기를 직접 '켠' 관측을 (외기온도 구간 x 시간대)별 집계, 14일 안 서로 다른 3일 이상이면 정차 중 음성+팝업으로 제안, 수락 시 규칙 추가, 거절 시 30일 재제안 없음 | [구현] 단위 테스트까지. 서로 다른 3일 누적·제안 팝업·30일 거절은 에뮬레이터 미검증 |
| 체감 온도 유지(외기온 기반 보정) | 설정에서 켬(기본 꺼짐). 외기온 30℃ 이상 -1℃/35℃ 이상 -2℃, 0℃ 이하 +1℃/-10℃ 이하 +2℃를 목표 온도에 더하고 차량 허용 범위로 맞춤. 외기온 없음·범위 밖이면 보정 없음. 보정 사실을 화면 문구에 표시 | [구현] 외기온만 사용(일사량·체감 센서·개인 학습 보정 없음) |
| 스마트 내외기 | 설정에서 켬(기본 꺼짐). 대기질 나쁨 -> 내기, 내기 10분(나쁨 20분) 초과 -> 외기, 공기 개선 시 자동 내기만 외기 복귀, 사용자가 직접 바꾸면 10분 보류, 재결정 최소 간격 5분. 주행 중에도 동작(음성 한 줄) | [구현] 대기질은 동의 시 선택 지역 모델 추정(참고용), 아니면 가공 샘플 |
| 주행 중 | 한 줄 안내만(최근 동작·내외기 상태). 열려 있던 팝업·탭·편집이 사라짐 | [구현] |

**차량 특화 요소**
- Pleos Vehicle SDK의 HVAC/시트/핸들 열선 속성을 capability 확인 후 읽고 쓰며, 기어(주행/정차) 신호로 UX를 분리합니다. 속성마다 지원 영역이 달라 운전석 포함 영역을 속성별로 골라 사용합니다(운전석 1열 좌만 제어).
- 외기온도는 차량 속성(ENV_OUTSIDE_TEMPERATURE) 15초 폴링.

### 주행 안전 설계
- **DO(주의분산 최적화) 선언**: 앱·액티비티에 `distractionOptimized` 메타데이터 선언.
- **정차/주행 UX 분리**: 모든 조작·편집은 정차 중에만. 주행 중에는 읽기 전용 한 줄(독립 검증에서 D 기어 40km/h 주입 시 확인 팝업이 열려 있어도 닫히고 한 줄만 표시됨을 확인).
- **자동 적용은 주행 중 절대 하지 않음**(정차 전환 시에만). 스마트 내외기만 주행 중 자동 동작하며 음성 한 줄로만 안내.
- **쓰기 실패 고지**: 공조 전원이 꺼져 있으면 풍량 등 쓰기가 거부될 수 있으며, 앱은 전원을 임의로 켜지 않고 항목별 성공/실패와 오류 코드를 '최근 적용' 줄에 표시.

## 4. 주요 사용 시나리오

**사용자**: 한 차를 함께 쓰는 가구, 더위·추위에 민감한 운전자, 출퇴근 루틴이 일정한 운전자 (기획 원문의 타깃)

**이용 흐름 (에뮬레이터 시연 기준)**
1. 탑승 후 정차(P) 상태에서 프로필을 선택하면 프로필 항목이 적용됩니다. 에뮬레이터에서 프로필 생성 후 P 전환 시 '최근: 7건 적용'과 Virtual Console 값 반영을 확인했습니다.
2. 외기온도·시간대·날씨 규칙이 해당되면 프로필 위에 덮어씁니다(예: 심야 규칙이 프로필 풍량 5를 2로 적용).
3. 자주 켜는 조작이 쌓이면 정차 중 "자동으로 켤까요?"를 제안하고, 수락하면 규칙이 추가됩니다(이 흐름은 단위 테스트까지, 에뮬레이터에서는 날짜 의존으로 미검증).
4. 스마트 내외기를 켜 두면 대기질 나쁨일 때 내기 전환, 내기가 오래되면 외기 복귀를 음성 한 줄로 알립니다(에뮬레이터에서 SIM 주입으로 확인. release 앱은 기본이 '보통' 고정이므로 설정의 ‘시연용 날씨·대기질’에서 대기질을 나쁨으로 골라 시연하며 ‘시연 값’ 배지가 표시됨. 시연 선택 UI 는 2026-11-11 후속 검증에서 에뮬레이터 화면으로 확인: 비+나쁨 선택 시 '시연 값' 배지와 규칙 매칭, 증거 48~50).
5. 주행 중에는 한 줄 안내만 보이고 조작은 정차 후에 합니다.

## 5. 개발 계획

**개발 환경**: Pleos Connect 에뮬레이터(AAOS 기반), Kotlin, Jetpack Compose, 최소 SDK 28. 앱 ID `com.hmgcarapp.myclimate`.

**Pleos SDK 사용**

| SDK | 사용처 |
|---|---|
| Vehicle (SDK 2.3.2) | HVAC·시트 열선/통풍·핸들 열선 읽기/쓰기(capability 체크, 권한 CONTROL_CAR_CLIMATE), 기어, 외기온도 |
| TextToSpeech | 제안·내외기 전환 음성 안내 |

Pleos 디자인시스템 컴포넌트와 주행 규제 연동(UX 제한 신호)을 사용합니다.

**기획과 다르게 구현한 이유 (세 가지로 구분)**
- **SDK·플랫폼 한계**: 운전자 프로필 ID 신호 없음(좌석별 착석 Boolean만 있음), 시동 신호 없음(`IgnitionState` 열거형만 있고 조회 API 없음), 경로 형상·터널 정보 없음, 일사량·강수 센서 없음.
- **안전·개인정보·약관 판단**: 공조 적용은 정차 중에만, 날씨 호출은 동의 후에만 하고 기기 위치 대신 선택 지역의 대표 좌표만 보냄, 위치 권한 미사용, Open-Meteo 무료 티어의 비상업 범위 안에서만 사용.
- **시간·범위상 미구현**: 개인 학습 기반 체감 보정, 기상청·에어코리아 직접 연동(Open-Meteo 로 대체), 동승석·뒷좌석 프로필, 부팅 시 서비스 시작(에뮬레이터 탐침에서 동작했으나 구현하지 않음).

**기획 대비 달라진 점**

| 원문 기획 | 구현 결과 |
|---|---|
| 차량 사용자 프로필/스마트폰으로 운전자 자동 인식 | 프로필 ID 신호가 SDK 에 없어(좌석별 착석 여부만 있음) **불가**. 탑승 시 정차 중 직접 선택 |
| 시동 감지로 탑승 시점 판단 | 시동 신호는 SDK 에 없다(`IgnitionState` 열거형만 있고 조회 API 가 없음). 부팅 시 서비스 시작은 에뮬레이터 탐침(`docs/research_2026-11-10.md`)에서 동작했으나 구현하지 않았다. **앱 실행/정차 전환 시 적용** |
| 터널 진입 전 내기 전환(NaviHelper) | 터널 정보를 주는 경로 형상 API 가 없어 **제외** |
| 체감 온도 유지 모드(일사량·주행시간 기반 개인 체감 보정값) | **축소 구현**: 외기온 기반 목표 온도 ±1~2℃ 보정만 있음. 일사량·주행시간·개인 학습 보정값은 없음 |
| 기상청·에어코리아 API 연동 | **Open-Meteo(키 없음)로 대체**. 위치 권한 없이 설정의 '지역 선택'(주요 도시 10곳, 기본 서울)의 대표 좌표로 날씨코드·PM10·PM2.5를 받아 맑음/흐림/비/눈과 환경부 4단계로 변환. 대기질은 약 45km 격자 모델 추정이라 '참고용 추정'으로 표기. 사용자 동의 전·실패 시에는 마지막 성공값 또는 맑음·보통 고정 '기본 샘플'. 화면에 출처 배지('실시간 · Open-Meteo · 선택 지역'/'마지막 값 · HH:mm'/'기본 샘플'/'시연 값')를 항상 표시. 무료 비상업 이용 범위. 에뮬레이터 실호출은 2026-11-11 후속 검증에서 확인(호스트 curl 값과 앱 표시 등급 일치, 증거 44·68) |
| 비 오는 날 규칙·미세먼지 내기 전환 시연 | 실시간 값이 마침 비·나쁨일 때만 자연 발생하므로 네트워크와 무관하게 설정(정차 중)의 ‘시연용 날씨·대기질’ 선택으로 재현하며 화면에 '시연 값' 배지 표시(메모리 전용, 저장 안 함). debuggable 빌드는 SIM 방송으로도 가능 |
| 습관 학습(모든 조작) | '켜기' 조작(시트 열선/통풍·핸들 열선·에어컨·내기)만 대상. 위치·음성은 저장하지 않음 |
| 미세먼지 나쁨 지역에서 내기 유지 | 대기질 나쁨 -> 내기, 장시간 내기 -> 외기 규칙(선택 지역 모델 추정 또는 시연 값 기준; 샘플·30분 넘은 값으로는 자동 전환하지 않음). 사용자가 직접 바꾸면 10분 보류 |

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 반복되는 공조 조작을 줄이고 주행 중 시선 분산을 줄이는 것을 목표로 합니다. 실제 감소 효과는 실차로 측정한 바 없으며, 이 문서는 효과 수치를 주장하지 않습니다.
- **타깃 고객**: 한 차를 여러 명이 쓰는 가구, 더위·추위에 민감한 운전자, 출퇴근 루틴이 일정한 운전자 (기획 원문).
- **예상 지표 [기획 가정]**: Pleos Connect 적용 10만 대 x 설치율 20% 가정 시 MAU 약 1.6만 명, 30일 리텐션 50% 이상 목표. 근거 자료가 없는 가정이며 구현·측정 결과가 아닙니다.
- **향후 계획 (구현·검증하지 않음)**: 개인 학습 기반 체감 보정 고도화(현재는 외기온 기반만), 현재 위치 기반 날씨·대기질(위치 권한 필요), 공공데이터(기상청·에어코리아) 연동, 터널 연동과 운전자 자동 인식(해당 API 가 공개될 때).

### 품질 체계 (구현 결과)
- 단위 테스트(clean 빌드): core 82개(고유), my-climate 185개, 실패 0.
- 코드리뷰 6회(결함 지적 수 17 -> 22 -> 14 -> 4 -> 1 -> 0), 반영 후 종료.
- 독립 런타임 검증(에뮬레이터, 코드 수정 없음): 11개 시나리오 PASS 9 / FAIL 0 / UNCERTAIN 2(습관 3일·거절 30일, 가로/세로 전환). 스마트 내외기의 5분 최소 간격은 일부 독립 확인 불가.
- 2026-11-11 후속 검증(Open-Meteo·체감 유지·시연 값, 에뮬레이터, 인터넷 연결): 통과 7 / 실패 1(전체 삭제 시 동의 미초기화 D-6) / 일부 UNCERTAIN(기본 샘플 전환, 체감 유지의 clamp·외기온 없음). D-6 은 수정 후 같은 날 재검증에서 PASS(M1), 철회 뒤 소켓 일부가 CLOSE_WAIT 로 남는 점(D-7)은 남아 있으며 신규 호출은 없었습니다. 근거: [../verification.md](../verification.md) 맨 아래 두 절(증거 40~77).
- 개인정보: 프로필·규칙·습관 통계만 기기 내 저장. 날씨·대기질을 위해 선택 지역의 대표 좌표만 Open-Meteo 로 보내며(기기 위치·식별자 없음, 최초 고지 동의 후에만, 설정에서 철회 가능), 출처는 Open-Meteo(CC BY 4.0)·CAMS로 앱 설정과 README에 표기.
- 설정에서 '학습 기록 지우기'/'모든 데이터 삭제' 제공. '모든 데이터 삭제'는 인터넷 사용 동의와 선택 지역도 처음 상태로 되돌리고 최초 고지를 다시 띄움(단위 테스트 및 2026-11-11 재검증으로 에뮬레이터에서 확인, 증거 70~77).

### 알려진 한계 (정직한 고지)
- **환경상 미검증**: 습관 학습의 서로 다른 3일 누적·제안 팝업·거절 30일, Portrait 등 화면 방향 전환, 스마트 내외기 5분 최소 간격(SIM 없이), 음성 청취(TTS 재생 완료 로그만 확인), 실차 동작.
- 차량 공조 서비스 초기화 전(부팅 직후·첫 실행 직후 최대 수 분)에는 SDK가 기본값을 돌려줘 에어컨·내기 표시가 실제와 다를 수 있음. 독립 검증에서 실제로 온도 0.0℃·에어컨 꺼짐·내기 켜짐이 약 3분 표시됨(`evidence/s2_initial_mismatch_temp0_acOff_recircOn.png`). 이후 온도·풍량은 범위 밖이면 표시하지 않도록 수정하고 에뮬레이터에서 재확인(앱 문서 기준). 에어컨·내기 불리언 기본값은 검증 불가.
- 차량 서비스가 비정상 종료되면 앱도 종료될 수 있음(Car 라이프사이클 리스너 미등록, 재실행 필요).
- 첫 실행에서 차속 권한 허용 전에는 차속 읽기 경고가 반복되며 재시작 후 해소.
- 공조 전원이 꺼져 있으면 풍량 등 일부 쓰기가 거부될 수 있음(앱은 전원을 켜지 않음).
- 자동 적용은 앱 실행당·정차 구간당 1회라, 같은 정차 구간에 앱을 닫았다 다시 열면 한 번 더 적용되어 사용자가 바꾼 값을 덮어쓸 수 있음.
- 송풍 방향은 쓰기만 하며 현재 값 읽기·변경 감지 없음. 차량이 지원하지 않는 항목은 적용되지 않음.
- Open-Meteo 공식 약관에 따르면 무료 API 의 웹서버 로그에 좌표 같은 정보가 남을 수 있고 90일 뒤 삭제됩니다. 이 앱이 보내는 것은 선택 지역의 대표 좌표와 접속 IP 이며, 설정 화면과 최초 동의 팝업에 이 로그 최대 90일 보관 안내를 표시하는 것을 에뮬레이터에서 확인했습니다(`K-regress-FINAL-B.md`).
- 운전석 착석 확인 팝업(정차 중 '마지막으로 사용한 프로필로 맞출까요?')은 앱이 SDK 의 착석 Boolean 을 그대로 신뢰하며 자동 적용은 없습니다. 에뮬레이터 관측이 회차에 따라 반대로 나와(SDK Vehicle 2.3.2 의 변환이 값 1 을 true 로 처리하는 것이 원인 후보) 동작을 확정하지 못했고, 실차 값은 확인하지 못했으며, 반전 보정은 하지 않았습니다. '맞추기' 적용 동작(풍량 6→3)만 확인했습니다.
- 날씨·대기질: Open-Meteo 무료(비상업) 티어라 상용화 시 유료 전환 또는 공공데이터 교체 필요, 대기질은 약 45km 격자 모델이라 참고용, 값은 선택 지역 기준. 에뮬레이터 실호출·동의 팝업 화면은 2026-11-11 후속 검증에서 확인했고(증거 40·44·67·68), 철회 뒤 닫히지 않은 HTTPS 소켓이 남는 점(D-7, 신규 호출 없음)은 미조치입니다. 비·미세먼지 시나리오는 설정의 시연용 선택(실데이터 아님, 저장 안 함)으로 재현. 체감 온도 유지는 외기온 기반 보정뿐이며 에뮬레이터에서 보정 적용(외기 36℃ 목표 -2℃, 한파 +2)을 확인했으나 범위 제한(clamp)·외기온 없음 경로는 확인하지 못함(증거 54~57). 저장 데이터는 기기 내 평문 저장(암호화 미적용).
- 미결 사항: 스마트 내외기 해제 시 내기 유지 여부(사용자 결정 대기, 앱 문서 D9).
- 에뮬레이터 HVAC 리스너 동작은 환경 의존.
